# Hookrail P0 Baseline — 2026-06-11

**Protocol (spec §11):** payload 1KB · healthy consumers (instant 200) ·
2min warm-up + 10min sustained · generator on a separate machine.
**Hardware:** MacBook Air (M1) generator → Mac mini (M4, 16GB) running the
stack under Docker on OrbStack, over Wi-Fi (5 GHz).
**Versions:** hookrail 1a4130b · postgres 16 · redis 7.

Latency column = **ingest commit → consumer completion**: a conservative
proxy for §11's "202 response → consumer 2xx receipt" (the commit strictly
precedes the 202, so published numbers err larger, never smaller). All
timestamps are the target's clocks — generator time is never compared
against target time.
Duplicates come from the receiver's /stats ledger (receipts − distinct), not
from PG. Duplicate budget: 0 in steady state. Stranded must be 0 (§11).

**Honest caveats:**

- The first run attempted (fan-out 1) failed against the shipped 50 rps
  per-endpoint default rate limit; the default was raised to 1000 rps /
  2000 burst (commit 1a4130b) before all published runs — a protocol
  deviation. The failed attempt was aborted by the script's own warm-up
  drain gate and published nothing; its backlog was confirmed fully
  drained (0 non-terminal deliveries, 0 duplicates) before the published
  runs started.
- Fan-out 3 took three attempts: the first was aborted by the warm-up
  drain gate against single-worker delivery capacity (see worker-replica
  caveat below); the second was aborted by the protocol's failure
  threshold when the target's Wi-Fi dropped mid-sustained-window (band
  shift on reconnect — the target stayed healthy and drained everything
  it had ingested); the published run is the third attempt. Neither
  failed attempt published numbers.
- Target ran 4 worker replicas (`docker compose up -d --scale worker=4`)
  instead of the compose default of 1 — another protocol deviation. A
  single worker replica (8-goroutine pool) measured ~244 deliveries/s:
  enough to pass fan-out 1 only deep in the queueing knee (e2e p95/p99 of
  15.8 s / 18.6 s on an earlier valid single-worker run), and insufficient
  for fan-out 3's 600 deliveries/s (its warm-up drain gate aborted the
  run). Scaling workers is the designed mechanism (CAS claim + lease
  fencing); both published rows reflect the 4-replica config.
- Target services are containerized under an OrbStack VM on macOS, not
  bare-metal Linux.
- Generator → target link is Wi-Fi (5 GHz, both machines), not wired
  ethernet.
- This is not the spec's 4-ARM-core reference box; the ~1k events/s
  validation target does not apply to this run. Rate used: 200 ev/s, the
  committed k6 profile default.
